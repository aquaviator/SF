You are a virtual developer agent working on a multi-tenant staff-scheduling SaaS with PostgreSQL via Drizzle ORM, a Node.js/Express back end, React + Tailwind front end, and Gmail SMTP for email.

**Task:** Implement secure Change Password, Change Email, and Forgot Password flows for both Owner (in Business → Owner Details) and Staff (in Account), plus add “Forgot Password” on the Login page.

---

### 1. Database Schema Updates  
In your Drizzle schema or via migration, alter `users` table to add:
```sql
ALTER TABLE users
  ADD COLUMN email_change_token VARCHAR(64),
  ADD COLUMN email_change_expires TIMESTAMPTZ,
  ADD COLUMN email_change_new TEXT,
  ADD COLUMN reset_password_token VARCHAR(64),
  ADD COLUMN reset_password_expires TIMESTAMPTZ;
2. Back-End API Routes
A. Change Password
POST /api/users/me/password

Body: { currentPassword, newPassword }

Authenticated via session/JWT

Logic:

Verify bcrypt.compare(currentPassword, user.passwordHash)

If valid, hash newPassword, update passwordHash, clear reset_password_token fields.

Invalidate existing sessions/tokens.

Return 200.

B. Change Email
POST /api/users/me/email

Body: { newEmail, currentPassword }

Logic:

Verify password.

Ensure newEmail not in use.

Generate email_change_token, set email_change_expires = now()+1h, email_change_new = newEmail.

Send email to newEmail with link:
https://app.shiftflo.com/confirm-email?token=<token>.

Return 200.

GET /api/auth/confirm-email

Query: ?token=

Logic:

Lookup user by email_change_token and email_change_expires > now().

If valid, set email = email_change_new, clear email-change fields.

Return 200 or redirect to success page.

C. Forgot Password
POST /api/auth/forgot-password

Body: { email }

Logic:

If user exists, generate reset_password_token, set reset_password_expires = now()+1h.

Send email to email with link:
https://app.shiftflo.com/reset-password?token=<token>.

Always return 200 (“If that account exists…”).

GET /api/auth/validate-reset

Query: ?token=

Logic:

Verify token and expiry.

Return 200/400.

POST /api/auth/reset-password

Body: { token, newPassword }

Logic:

Lookup user by reset_password_token and reset_password_expires > now().

Hash newPassword, update password, clear reset fields.

Invalidate sessions.

Return 200.

3. Front-End Integration
A. Owner & Staff Profile Pages
Add Change Password form (current + new + confirm) calling POST /api/users/me/password.

Add Change Email form (newEmail + currentPassword) calling POST /api/users/me/email.

Display success/error toasts; require re-login after password change.

B. Login Page
Add “Forgot your password?” link to /forgot-password.

C. Forgot Password Page (/forgot-password)
Form with email input. On submit, call POST /api/auth/forgot-password, show generic success message.

D. Reset Password Page (/reset-password?token=…)
On mount, call GET /api/auth/validate-reset?token=…, if invalid show error.

Form with newPassword + confirm; on submit call POST /api/auth/reset-password, then redirect to /login with success toast.

E. Confirm Email Page (/confirm-email?token=…)
On mount, call GET /api/auth/confirm-email?token=…, show success or error, then update UI or redirect.

Output:
Reply only with the precise code diffs and new files your agent would create:

Drizzle migration for users table changes

src/routes/users.ts updates (change-password, change-email)

src/utils/mailer.ts snippet for sending change-email and reset-password emails

client/src/pages/ProfileOwner.jsx & ProfileStaff.jsx updates for forms

client/src/pages/ForgotPassword.jsx, ResetPassword.jsx, ConfirmEmail.jsx
