A few things to check and tweak in your SidebarNav so that the avatar actually renders:

Are you actually receiving a photoUrl?

Open your network tab (or add a console.log(userProfile) right after the query) to verify that the shape coming back from /api/users/:id includes a non‐null photoUrl and that it’s a fully‐qualified URL (e.g. https://…/avatars/123.jpg), not just a relative path or a Base64 data URI.

If it’s missing or wrong, you’ll never see an <img>—React will skip into your “initials” fallback.

React’s innerHTML fallback can clobber React’s DOM
You’re doing this in your onError handler:

tsx
Copy
Edit
onError={(e) => {
  const target = e.target as HTMLImageElement;
  target.style.display = 'none';
  target.parentElement!.innerHTML = `<span class="text-white text-sm font-medium">${getUserInitials()}</span>`;
}}
Directly setting innerHTML inside a React‐managed tree can confuse React’s reconciliation. Instead, opt for React state:

tsx
Copy
Edit
const [imgErrored, setImgErrored] = useState(false);

// …in JSX…
{userProfile?.photoUrl && !imgErrored ? (
  <img
    src={userProfile.photoUrl}
    alt="Profile"
    className="w-full h-full object-cover"
    onError={() => setImgErrored(true)}
  />
) : (
  <span className="text-white text-sm font-medium">{getUserInitials()}</span>
)}
This way React cleanly switches from <img> to <span> without any ad‐hoc DOM surgery.

Check your container’s background vs. image transparency
You’ve got:

html
Copy
Edit
<div className="w-10 h-10 bg-blue-600 rounded-full flex items-center justify-center overflow-hidden">
  { /* …img or initials… */ }
</div>
If your image itself has large transparent areas (e.g. PNG with alpha) you might be seeing a big blue circle instead of the picture. Try adding a quick red border to debug:

html
Copy
Edit
<div className="w-10 h-10 bg-blue-600 rounded-full overflow-hidden border-2 border-red-500">
If you see the red ring with nothing inside, the image really isn’t loading or is zero‐sized.

Ensure your query is enabled and firing
You’ve got enabled: !!user?.id. If user.id is ever 0 or undefined in your auth context, the fetch won’t run. Double‐check that useAuth() is providing the correct user.id by logging it:

ts
Copy
Edit
console.log("SidebarNav user:", user);
Cross‐origin / CORS / broken URL
If the photoUrl is pointing at a different domain or CDN that doesn’t allow cross‐origin <img>s, the browser may silently block it. Try opening the photoUrl directly in a new tab to confirm it loads.

Checklist
Log userProfile and make sure userProfile.photoUrl is truthy and correct.

Switch your onError from innerHTML hacks to React state (imgErrored).

Add a temporary border/outline to the avatar container to see if the image is zero‐sized.

Confirm that your query actually fires by logging tenantId, user, and userProfile.

Open the photoUrl directly in the browser to check for CORS or 404s.

Once you verify that you’re actually getting back a valid URL and React is rendering an <img> tag, you’ll see the photo in the sidebar. Let me know which step uncovers the culprit!
