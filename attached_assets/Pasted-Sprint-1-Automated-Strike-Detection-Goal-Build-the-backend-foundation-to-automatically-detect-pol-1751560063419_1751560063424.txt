Sprint 1: Automated Strike Detection

Goal: Build the backend foundation to automatically detect policy‐violations (no-shows, late-cancellations), assign strike points, and expose strike data via API—complete with logging and tests.

Run the migration and update Drizzle schema definitions.

Cron Jobs

No-Show Detection

Schedule a job at each shift’s start time + cancellationDeadline (from shift_policies)

Query all time_entries with no check-in → insert a strike (points = policy.noShowPoints, reason="no_show", reference_id=shift.id).

Log: console.log("⚠️ STRIKE_ASSIGNED", { userId, shiftId, points, reason, timestamp: new Date() })

Late-Cancellation Detection

Hook into your existing POST /api/shifts/:id/cancel route

If cancellation is within the policy’s cancellationDeadline, insert strike (policy.lateCancelPoints)

Log: console.log("⚠️ LATE_CANCEL_STRIKE", { userId, shiftId, points, timestamp: new Date() })

Clean-Slate Reset

Monthly cron job at midnight: for each user, subtract or zero out strike points older than resetPeriodDays

Log: console.log("🔄 STRIKE_RESET", { userId, removedPoints, timestamp: new Date() })

API Endpoints

GET /api/staff/:userId/strikes

Returns current total points + history array

Log: console.log("🏷️ GET_STRIKES", { userId, timestamp: new Date() })

Guard Claim Endpoint (POST /api/shifts/:id/claim)

Before creating assignment, fetch total points; if ≥ policy.maxStrikePoints, reject with 403

Log:

on check: console.log("🔐 CLAIM_GUARD", { userId, totalPoints, maxPoints, timestamp: new Date() })

on block: console.log("🚫 CLAIM_BLOCKED", { userId, shiftId, totalPoints, timestamp: new Date() })

Testing

Console Output Assertions:
