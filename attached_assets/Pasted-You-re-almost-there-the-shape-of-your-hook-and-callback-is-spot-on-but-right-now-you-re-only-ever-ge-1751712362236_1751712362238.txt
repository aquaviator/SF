You’re almost there—the shape of your hook and callback is spot-on—but right now you’re only ever getting a photoUrl string from your PhotoUpload component and shoving it straight into your profile update. What you really need is a two-step process:

Upload the raw file (or data URL) to your server (or S3/etc.)

Get back a permanent photoUrl from that upload endpoint

Mutate your user profile with that new photoUrl

As it stands, your photoUploadMutation is literally just calling your profile-PUT with whatever string your component hands you—so if PhotoUpload gives you a local-blob URL (or base64 preview), that never actually lives on your CDN and will vanish on refresh.

What to change
Have PhotoUpload hand you the actual File instead of a string.
If you control that component, add an onFileSelect(file: File) prop, and let it continue to render previews internally.

Make your mutationFn accept a File and do the FormData upload

const photoUploadMutation = useMutation<File, Error, File>({
  mutationFn: async (file) => {
    const form = new FormData()
    form.append("photo", file)
    form.append("userId", String(user?.id))
    // have apiRequest detect FormData and skip JSON headers
    const res = await apiRequest("POST", `/api/users/${user.id}/photo`, form)
    if (!res.ok) throw new Error("Upload failed")
    const { photoUrl } = await res.json()
    return photoUrl  // the permanent URL
  },
  onMutate: () => setIsUploadingPhoto(true),
  onSuccess: (photoUrl) => {
    setIsUploadingPhoto(false)
    toast({ title: "Success", description: "Photo updated!" })
    // now call your existing profile-URL updater:
    handleDirectPhotoChange(photoUrl)
  },
  onError: (err) => {
    setIsUploadingPhoto(false)
    toast({ title: "Error", description: err.message, variant: "destructive" })
  }
})

Drop your inline onImageChange that passes strings

Use onFileSelect for raw File objects

Show the spinner via isLoading={isUploadingPhoto}

Kill the now-unused state/handlers

Remove pendingPhotoUrl, photoFile, handlePhotoChange, uploadPhoto, etc.

You only need isUploadingPhoto and your two mutations.

(Optional) Optimistic rollback
If you want to immediately swap in a preview URL and then roll it back on error, use React-Query’s onMutate/onError hooks. But honestly, with your loading spinner and toast, a simple “wait until the upload returns” UX is perfectly fine.

With those three changes:

The browser will send a real multipart upload,

You’ll get back a durable URL from your server/CDN,

And then you re-use your handleDirectPhotoChange to stash it on the user record.
